- Bounded, verified synthetic callback persists an inbound event/job atomically before 200; duplicate same event is a no-op; bad signature/body/conflicting identity or unavailable persistence never succeeds or creates domain/jobs/outbound effects.

Idle waiting makes no hot DB polls or persistent health queries. Unix hints carry no payload/authority and failures do not undo durable ingestion.
- Claims use short transactions and generation-checked leases; concurrent claim/reclaim cannot commit stale completion. Work completion atomically creates one logical outbox effect. External sends happen outside DB transactions.
- Fake-provider client is bounded/deadlined, numeric-loopback-only, with proxy/redirect escape disabled. Known acceptance versus unknown send outcome remain distinct; unknown outcomes are not blindly resent. No real provider URL, credentials, auth account, dashboard/business endpoint or API contract beyond the local test slice is implemented.
- API/worker are separate Go processes from one backend module, with owned cancellation/shutdown and useful local documentation. Use selected pgx/sqlc/Goose at their real boundaries, not hand-written provider frameworks. Dependency/tool versions are pinned; caches must not pollute tracked work.
