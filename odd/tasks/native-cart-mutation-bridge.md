### Selected technical contract (S3–S15; admission accepted, consumer independent proof pending)
- Public shape: AdmitNativeEdit(ctx, local, MenuClaim, slot, Call) (NativeActionRef,error); RecoverNativeEdit(ctx, ref, lease) (NativeActionClaim,bool,error); ClaimNextNativeEdit(ctx, lease) (NativeActionClaim,bool,error); ExecuteNativeEdit(ctx, claim) (Result,error). Four methods implement three behavioral seams; restart discovery is explicitly distinct from known-reference recovery.
- NativeActionRef and NativeActionClaim have private fields and no public parsing/JSON authority constructor. Ref exposes the server OperationID; claim exposes its Ref. Only admission or persisted discovery/recovery produces these values. Store is restaurant-bound; persisted source establishes local conversation/business/sender scope. No caller needs private fields or a new model DTO.
- Issuer: trusted backend runtime owns the actual current MenuClaim and stable nonnegative int64 slot (0 through MaxInt64, matching RegisterExecution's slot domain). Model output supplies only one validated EditCall/Add/Remove/SetNote with trusted cart and expected Version. Create/read/draft/preview calls are not admitted native edits. Canonical encoding/decoding and the existing resultBudget validation are reused, not replaced.
- Admission locks the existing ownership/source/control/job prefix, verifies the actual job identity/generation/attempt/source/route and fresh database lease, then current mode=ai and exact original claim epoch. Cart ownership is validated; stale expected cart version is ErrStale. Canonical plan plus distinct native admission/work/provenance is committed atomically. A pre-existing canonical call without native admission cannot be promoted. With valid current admission authority, identical event/slot intent returns the same Ref/operation without new work; changed intent or an unadmitted existing slot is ErrConflict. After takeover or epoch change, use recovery, not re-admission.
- Durable native lifecycle is independent of app.jobs reply state. Store event/slot/canonical operation/source/tenant/conversation and original admission provenance immutably. Business completion and execution lease are orthogonal: a nullable committed marker and an independently nullable deadline/counters represent pending/leased and committed/history-leased states; do not duplicate them in contradictory completed/leased flags. Discovery selects only unfinished admitted work; targeted recovery may lease completed work for history only. No reply-job resurrection, legacy backfill or removal of app.jobs event uniqueness.
- Lease input for the NEW native recovery/discovery methods is inclusive 1 millisecond through 5 minutes. No default or clamping. PostgreSQL microsecond precision is authoritative; return/capture the actual persisted deadline, never rely on a caller clock or exact Go nanosecond retention. This native-only bound does not change ClaimMenu, legacy lease behavior, or any test/process timeout. Each new transaction uses the existing 5-second operation context/1-second rollback-cleanup convention.
- Both claim methods: true only after a known committed fresh acquisition, with a valid nonzero Claim. false,nil means no claimable work at this moment (including an already live lease or not-yet-due work), with zero Claim; it is NOT model/reply permission and does not mean no durable work exists. Any error returns false and zero Claim. Invalid/foreign refs are errors, never a false,nil queue miss. ClaimNext needs neither a remembered event/ref nor a model call.
- Errors: cart.ErrInput for nil/invalid API arguments, zero Ref, unsupported Call/slot or out-of-range lease; cart.ErrNotFound uniformly for missing/foreign persisted Ref; foundation.ErrStaleLease for zero/foreign/stale/expired source admission claim or business execution claim. NEW cart.ErrNativeAdmissionClosed (to be defined in native_actions.go, message "native cart admission is no longer permitted") distinguishes structurally valid MenuClaim but current AI/epoch permission lost. cart.ErrConflict identifies changed canonical intent/unadmitted occupied slot; cart.ErrStale identifies new-mutation expected-Version mismatch; cart.ErrStoredData identifies malformed stored native admission/intent/results; cart.ErrUnavailable covers database/uncertain commits without pretending success. Existing domain errors such as ErrUnavailableItem/ErrLimit propagate without relabeling. Native lease generation/attempt counters are nonnegative PostgreSQL bigint values; exhausting either at MaxInt64 returns existing ErrLimit before any increment/write, never false,nil. Invalid lease duration is ErrInput; an expired execution claim is ErrStaleLease; expiration makes persisted work eligible for a fresh recovery claim, not cancellation. A live competing lease remains no claimable work (false,nil). These outcomes add no further error taxonomy. Parent cancellation/deadline errors follow existing context conventions.
- Execution reloads and validates source/scope/native admission/canonical operation and current business claim generation/attempt/deadline under transaction locks BEFORE reading a historical result. Current AI mode/epoch is not execution permission. For unfinished work only, lock cart and enforce expected Version before domain mutation. Recheck database clock after blocking resources and before commit against the locked captured lease deadline. Operation/result plus business completion/lease retirement commit atomically. Never check freshness against a deadline already cleared by the transaction.
- Completed replay is RecoverNativeEdit followed by ExecuteNativeEdit under a NEW fresh business claim: exact stored Result, no fresh cart CAS, repricing, availability inference or mutation. Old claim after completion is stale; recovery never changes canonical intent or operation. Recovery/discovery precedes a model retry when persisted work exists; false queue results cannot independently authorize re-modeling old messages. Exact backend Result drives downstream state.
- Public acceptance coverage: admission success/no mutation; identical/changed same-slot behavior; refusal to promote legacy plans; wrong source/epoch/current mode and expired claims; all three supported edits; zero/foreign Ref and Claim; lease lower/upper boundaries and invalid adjacent values; no-work false,nil vs safe errors; lease contention/reclaim; discovery without remembered Ref/model; fresh authority before cached history; takeover/no-reply survival; stale CAS rejection without mutation; exact historical replay/no duplicate effect; uncertain commit not reported as success.
